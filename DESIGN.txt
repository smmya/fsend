fsend 原理与实现思路
审查基线：WorkBuddy fastsend d07ce11；整理版本：v1.2.0；日期：2026-11-17。

1. 角色与连接
默认由接收方监听、发送方连接；-R 反转 TCP 建立方向。
数据角色始终不变：发送方组织 offer、文件数据与 done，接收方确认并落盘。
不提供中转、自动端口映射或 NAT 穿透。UDP 路由探测得到本地出口地址，而非公网地址。
每次启动生成新的 15 字节随机 PSK，通过 fs://host:port#CODE 共享。
这个密钥等价于一次性访问凭据，应通过可信渠道传递，不应进入公开日志。
监听端拒绝错误握手后继续等待，但不是抗连接洪泛服务器；部署时限制开放时间和可访问来源。

2. 握手与加密
协议 v1 握手使用临时 X25519 密钥对与双方各 16 字节随机数。
HKDF-SHA256 从 ECDH 共享值与 PSK 派生两个方向的独立 AES-256-GCM 密钥。
双方用加密认证帧检查协议版本与数据角色。不同方向采用不同密钥和 nonce 标签。
nonce 由方向标签与严格递增的 64 位计数器组成。重放、修改或错序会使认证失败。
帧长在分配内存前限制为约 1 MiB。达到计数器上限时中止，不允许回绕复用 nonce。
当前保留原有 PSK 加 ECDH 方案，没有把手工设计协议替换为外部认证协议。
此审查及回归测试不构成密码学安全证明或独立第三方审计。

3. 数据模式
tar 模式把目录组织为流式 tar，经加密帧发送，不先落地整个归档。
接收端验证归档数据流的 SHA-256，再发送 doneack；失败时删除本次创建的文件。
serial 模式依次传送文件元数据、数据、结束帧、单文件 SHA-256 和回执。
目录使用 kind=dir 的零长度元数据项，保留空目录；旧客户端不一定支持这一扩展。
单文件确认失败时继续处理其余文件，但最终退出码为 1。已验证文件保留。
两端总校验按成功条目的 SHA-256 字符串累积；发送端也核对最终回执的哈希。
AEAD 已保护信道完整性；SHA-256 用于端到端的数据和落盘结果一致性确认。
进度统计是估计值：tar 的头部和填充包含在流量中，因此不能当作纯文件负载精确统计。

4. 文件系统边界
接收端用 os.OpenRoot 固定接收目录，以 os.Root 方法解析所有对端提供的路径。
这比先检查字符串再用绝对路径打开文件能更可靠地限制软链接路径穿越。
参考 Go 官方说明：https://go.dev/blog/osroot
纯字符串检查额外拒绝父目录段、绝对路径、控制字符、Windows 盘符、ADS 和设备名。
相同限制跨平台应用，以减少不同操作系统之间的名称歧义。
新文件使用 O_CREATE|O_EXCL 原子创建，同名时更换序号，不先检查再截断写入。
文件先以 0600 创建，完整接收后经已打开句柄设置普通权限位；目录以 0700 创建。
不恢复 setuid/setgid、所有者、ACL、时间戳、扩展属性、硬链接关系及目录权限。
不创建软链接、硬链接或特殊设备条目。已有目录合并，已有文件保留。
os.Root 并非对恶意本地管理员、挂载点或特殊文件系统的完整沙箱。
接收目录应属于运行用户，并与其他程序及其他不可信本地用户隔离。
整个任务不是原子事务：接收中的文件可见；错误清理尽力执行，强制退出可能留下文件。
已创建的空目录在失败后可以保留；不修改已有目录的权限或时间戳。

5. 资源与失败处理
默认接收上限 100 GiB 和 100000 个文件/目录条目。
额度按实际 tar 头或 serial 元数据累计，不只信任 offer 中的总数。
serial 接收额外限制实际读取长度，不允许声明小文件却无限写入。
握手上限 30 秒，单帧读写上限 10 分钟；监听的等待上限可配置。
监听失败和握手失败明确报错。错误密钥探测不会立即结束整个监听进程。
资源上限不能代替磁盘配额、防火墙、速率限制或操作系统权限控制。
运行过程中源文件和接收目录不应被其他进程修改；不支持断点续传或快照一致性。

6. 发布与安装
GitHub 为指定发布目标；提交身份通过用户已有的 Gitea 配置读取账号名称和邮箱。
只导入生产源码，不导入原 Git 历史、WORKPLAN、原始测试、演示数据、日志或二进制。
新增 security_regression_test.go 专门验证此次修复，独立于 WorkBuddy 的旧测试文件。
Actions 在 Linux/macOS/Windows 上检查，再交叉编译七个目标。
主分支首次出现的版本号会自动创建标签并发布，也支持标签触发；已有版本不会被覆盖。
依赖的第三方 Actions 固定到提交 SHA，普通检查只读，发布任务单独获得 contents:write。
构建不使用外部 Go 模块，CGO_ENABLED=0；发布包包含 SHA256SUMS。
安装脚本通过 HTTPS 请求 GitHub 获取正式 Release 和对应平台文件，检查哈希后安装。
哈希与二进制同源，不是独立签名，不能防御 GitHub 仓库或发布权限本身被控制。
源码没有附加开源授权许可；如需指定许可证，由仓库所有者另行选择。
